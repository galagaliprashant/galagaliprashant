### How I think as a builder

- **Problem first.** I ask "what breaks for the user?" before "which tool do we use?"
- **Systems over scripts.** One reusable framework beats a hundred one-off tests.
- **Ship small, then improve.** A working slice today beats a perfect plan next month.
- **Make quality visible.** Dashboards, reports and traceability, so everyone can see the state of the product.
- **Learned from 9 years on the inside:** voice assistants and smart devices at Samsung R&D, fintech at scale at Grab, connected aerospace hardware today.

### ⚙️ Why I love process and systems

Talent gets you started. **Systems are what got me here.** Every step of my career, from manual tester to automation to building products, came from running the same loop again and again, and improving the loop itself each time.

```yaml
# how_i_work.yml: the pipeline behind everything I've built
pipeline:
  trigger: a real problem              # not a tool, not a trend
  stages:
    - define:   requirements -> risks -> acceptance criteria
    - design:   architecture, test strategy, traceability
    - build:    small slices, version-controlled, reviewed
    - automate: CI on every push; no manual step done twice
    - ship:     behind quality gates
    - observe:  reports, logs, metrics
    - learn:    retro -> update the process itself
  on_failure: find the root cause, fix the system, not just the symptom
  schedule: continuous                 # same loop for products, teams and my own growth
```

- **Systems compound.** Each framework, pipeline or checklist I build makes the next piece of work faster and safer.
- **Process beats motivation.** A good system keeps running on the hard days. That's how I turned manual testing into automation, a career gap into shipped apps, and a blank repo into a working QA function.
